# Domain Class Model

- Authoritative source: [domain-class.puml](domain-class.puml)
- Related decisions: [ADR-0004](../adr/0004-mvp-architecture-and-cli.md), [ADR-0005](../adr/0005-kb-snapshot-and-lexical-retrieval.md), [ADR-0007](../adr/0007-provider-abstraction-and-offline-fallback.md)
- Related requirements: `REQ-001`, `REQ-010`, `REQ-020`, `REQ-104`, `REQ-107`

The model distinguishes implemented Pydantic ticket/classification, synthetic snapshot/retrieved-passage, extractive draft/citation, abstention, safety-routing, configured confidence-routing, conflict-detection, application-service, auditable-result, labeled evaluation-set, and aggregate evaluation-report contracts from planned provider contracts. Snapshot loading, hashing, allowlist filtering, persistence, section retrieval, evidence-derived deposit drafting, exact timeline validation, explicit duration-conflict abstention with source exposure, fee/verification abstention with canonical insufficient-knowledge routing, direct-buy/leverage refusal, explicit KYC/complaint outcome routing, strict below-threshold confidence routing, immutable audit-result composition, bounded offline CLI orchestration, and four-kind offline evaluation are implemented. Live fetching plus general semantic citation/conflict validation, confidence calibration, broader safety/review routing, audit persistence, provider cost data, the 30+ case corpus, and live-provider integration remain planned.
